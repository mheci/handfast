# Handfast 0.3.0

Handfast 0.3.0 ships one executable, `handfast` on Linux and `handfast.exe` on
Windows. It starts the daemon, talks to it, installs its own autostart, updates
itself and opens a window. The separate `handfastd` and `hfctl` programs are
gone.

## Install

Linux, Debian 12 or Ubuntu 24.04:

```sh
sudo apt install ./handfast_0.3.0_debian12_amd64.deb
systemctl --user enable --now handfast
```

Arch Linux:

```sh
sudo pacman -U handfast-bin-0.3.0-1-x86_64.pkg.tar.zst
systemctl --user enable --now handfast
```

The packages install `/usr/bin/handfast`, the systemd user unit
`/usr/lib/systemd/user/handfast.service`, and the license and third-party
notices. They replace the 0.2.0 `handfastd` package names in one step.

Windows 11, x64: open `handfast-0.3.0-x64.msi`. It installs per user to
`%LOCALAPPDATA%\Handfast` and adds a Start Menu shortcut named `Handfast` that
runs `handfast gui`. Then run:

```text
handfast service install
```

That registers the logon task and prints the firewall command when the rule is
missing. Run that printed command from an administrator prompt: a per-user
install cannot add the rule itself, and a logon task cannot answer the Windows
firewall prompt. Without the rule the daemon runs but discovers no peers.

Portable: download `handfast-x86_64-unknown-linux-gnu` or
`handfast-x86_64-pc-windows-msvc.exe` from the release, rename it to `handfast`
or `handfast.exe`, and run `handfast service install` to autostart it.

## Upgrading from 0.2.0

Windows: uninstall the 0.2.0 MSI once (Settings > Apps > Installed apps >
Handfast > Uninstall), then install 0.3.0. Windows Installer cannot replace a
per-machine product with a per-user one without elevation. 0.3.0 and later
upgrade in place.

Linux: `apt` and `pacman` replace `handfastd` with `handfast`. The state
directory and the store schema do not change, so the install keeps its device ID
and its pairings.

## What it does

```sh
handfast daemon            # run the daemon
handfast gui               # open the window
handfast status [--json]   # print the running daemon's status
handfast identity          # print this device's identity packet
handfast share --device <id> <path>
handfast service install|uninstall|start|stop|status
handfast update check|apply
handfast version
```

- UDP discovery on 1716, TLS 1.2 and TLS 1.3 links in 1716-1764 with pinned
  certificates, pairing, and the ping and battery plugins.
- File, text and URL share in both directions, with a safe incoming folder.
- A per-user autostart service: a Task Scheduler logon task on Windows, a
  systemd user unit on Linux.
- A self-updater that verifies `SHA256SUMS` and, on Windows, Authenticode.
- An `egui` window behind the `gui` feature.

State lives in `%LOCALAPPDATA%\handfast` on Windows and in
`$XDG_DATA_HOME/handfast`, or `~/.local/share/handfast`, on Linux. Use
`--data-dir` to override it.

The store schema, the data directory and the device identity are unchanged from
0.2.0. A 0.3.0 daemon opens a 0.2.0 `state.db` and reconnects to paired peers
without a new prompt.

## Known limits

- No macOS and no aarch64 build.
- The Windows updater refuses an unsigned asset. Self-update needs a signed
  release.
- On Linux the update trusts TLS and the `SHA256SUMS` published in the same
  release. A minisign signature is a follow-up.
- The real Android and KDE Connect desktop run in `docs/INTEROP.md` is still the
  P1 exit gate. CI proves the testkit and the production code, not a real phone.
- The firewall rule on Windows needs an administrator. The install prints the
  command instead of elevating.

## Verify

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` covers every asset in the release.
